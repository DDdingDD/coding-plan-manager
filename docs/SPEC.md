# Coding Plan Manager 产品与技术规格

> 文档状态：依据当前代码实现整理，描述现有行为，不作为未来功能承诺。
>
> 核对日期：2026-11-25
>
> 适用范围：Tauri 桌面应用、内置 Axum 反向代理、SQLite 持久化及 Vue 前端。

## 1. 产品概述

### 1.1 目标

Coding Plan Manager 用于统一管理多个 AI Coding Plan，并将每个聚合器暴露为一个本地 HTTP 端点。外部客户端只需配置聚合器的 `BASE_URL` 和 `AUTH_TOKEN`，即可由应用完成：

- 客户端鉴权与上游令牌替换；
- 按阈值轮转或模型匹配选择上游计划；
- Anthropic / OpenAI 兼容请求的 JSON、SSE 转发；
- 请求与响应留痕、Token 用量解析和统计；
- 多计划配置迁移与服务启停管理。

### 1.2 术语

| 术语 | 定义 |
| --- | --- |
| Coding Plan / 计划 | 一个上游 API 配置，包含 `base_url`、上游 `auth_token`、支持模型和启用状态。 |
| 聚合器 / Aggregator | 一个可独立启停的本地反向代理，绑定多个计划并使用一种路由策略。 |
| 绑定 / Binding | 聚合器与计划的有序关联，保存该关联的 `used_tokens`。同一计划可绑定到多个聚合器，各绑定用量独立。 |
| 当前计划 | 下一次请求优先使用的计划。阈值轮转下可表示手动固定；模型匹配下表示粘性或兜底目标。 |
| 历史统计 | 对 `messages` 表求和，记录已经发生的使用量，不因路由用量清零而改变。 |
| 路由用量 | `aggregator_plans.used_tokens`，用于阈值轮转和模型匹配中的最少用量比较，可清零。 |
| 小计里程 | 从指定起点统计、支持暂停和重置的独立视图，不删除消息，也不影响历史统计。 |

### 1.3 当前范围与边界

- 每个聚合器仅监听 `127.0.0.1`，不是面向局域网或公网的服务。
- 应用重启后不自动启动此前运行的聚合器，需手动启动。
- 单次请求只选择并调用一个上游；当前实现不向其他计划自动重试或故障转移。
- 不估算缺失的 Token 用量；上游未提供可识别的 `usage` 时记为 0。
- 不提供消息自动保留期或自动清理策略；消息由用户手动清空。
- 不提供多用户、权限分级、云端同步或令牌加密存储。

## 2. 系统结构与主流程

### 2.1 技术组成

- 桌面壳：Tauri 2；
- 前端：Vue 3、TypeScript、Vite、ant-design-vue；
- 代理：Rust、Axum、reqwest、Tokio；
- 数据库：SQLite（rusqlite，WAL 模式）；
- 原生文件及错误对话框：rfd。

### 2.2 请求主链路

```text
外部客户端
  │  Authorization: Bearer <聚合器令牌> 或 x-api-key
  ▼
127.0.0.1:<聚合器端口>
  │  重读聚合器配置 → 客户端鉴权 → 读取请求体/模型
  │  路由策略选择计划 → 替换为计划令牌 → 转发任意 method/path
  ▼
Coding Plan 上游
  │  JSON 整体响应 / SSE 流式响应
  ▼
聚合器
  │  原状态与业务响应回传客户端
  │  解析 usage → 更新绑定路由用量 → 写入消息 → emit message:new
  ▼
Vue 页面防抖刷新
```

配置与运行状态的关系：

- 代理处理每个请求时都从数据库重读聚合器配置，因此计划令牌、计划启用状态、绑定、阈值、当前计划和路由策略的修改即时生效。
- 端口修改必须先停止服务。
- 服务运行句柄仅保存在内存中；数据库中的配置不代表服务正在运行。

## 3. Coding Plan 管理

### 3.1 字段规则

| 字段 | 规则 |
| --- | --- |
| `name` | 必填，去除首尾空白后不得为空。 |
| `base_url` | 必填，去除首尾空白后必须以 `http://` 或 `https://` 开头。 |
| `auth_token` | 必填，去除首尾空白后不得为空；为上游服务令牌。 |
| `remark` | 可选，缺省为空字符串；更新时省略该字段表示保持原值。 |
| `models` | 可选模型名列表；各项去除首尾空白并忽略空项，数据库以逗号分隔保存。 |
| `enabled` | 新建时默认启用；更新时省略表示保持原值。 |
| `created_at` | 创建时生成，本地时间字符串。 |

`models` 的语义：

- 仅模型匹配策略使用；阈值轮转不读取该列表。
- 空列表表示该计划不参与模型匹配，但仍可作为当前计划承接无匹配请求。
- 匹配使用模型名精确字符串相等，不做前缀、大小写归一化或通配符匹配。

### 3.2 操作

- 支持新建、编辑、启用/禁用和删除。
- 列表默认遮蔽令牌，支持临时显示和复制；遮蔽只是界面展示措施。
- 列表显示该计划的历史 Token 与请求数。
- 删除计划会解除其在所有聚合器中的绑定；其历史消息不随计划删除。
- 被禁用的计划可继续保留绑定，但不参与自动路由，也不能通过命令层手动设为当前计划。

## 4. 聚合器与绑定

### 4.1 聚合器配置

| 字段 | 规则与默认值 |
| --- | --- |
| `name` | 必填，非空。 |
| `port` | 范围 1–65535，数据库内不得重复；留空时自动分配。 |
| `auth_token` | 创建时自动生成，格式为 `cpm-` + 32 位十六进制字符；常规编辑命令不提供修改入口。 |
| `strategy` | `threshold_rotation` 或 `model_match`，默认 `threshold_rotation`。 |
| `token_threshold` | 默认 1,000,000，最小为 1；仅阈值轮转用于路由判定。 |
| `current_plan_id` | 当前计划，可为空；其具体含义随策略变化。 |
| `base_url` | 派生值，固定为 `http://127.0.0.1:<port>`。 |
| `running` | 派生运行状态，不落库。 |

自动分配规则：

- 新建时优先在 8300–8399 中跳过数据库已配置端口，并通过实际 bind 检查本机可用性。
- 显式指定端口只校验范围和数据库内唯一性；操作系统层面的占用在启动时报告。
- 8300–8399 无可用端口且未显式指定端口时，新建失败。

### 4.2 服务生命周期

- 启动：绑定 `127.0.0.1:<port>` 并启动独立 Axum 服务；重复启动为幂等操作。
- 停止：取消服务任务并最多等待 5 秒；重复停止为幂等操作。
- 删除：先停止运行中的服务，再删除聚合器及其绑定；历史消息不删除。
- 退出应用：所有进程内代理服务随之停止。
- 端口被外部进程占用时，启动失败并向用户返回中文错误。

### 4.3 绑定管理

- 一个聚合器可绑定多个计划；同一计划在同一聚合器内最多绑定一次。
- 绑定有稳定顺序，支持上移、下移、追加和解绑。
- 保存绑定时按提交顺序去重，并要求所有计划存在。
- 重排或保留已有绑定时保留其 `used_tokens`；新绑定从 0 开始。
- “重置用量”将该聚合器所有绑定的 `used_tokens` 清零，不修改 `messages`，因此不影响历史统计和小计里程。
- 切换路由策略会清除 `current_plan_id`，避免沿用另一种策略的当前计划语义。

### 4.4 手动指定当前计划

- 命令层仅允许选择该聚合器已绑定且已启用的计划。
- 阈值轮转可传空值恢复自动轮转；已达阈值的计划在界面上不可选。
- 模型匹配可手动指定下一请求的粘性/兜底计划；命中其他模型后仍可能自动切换。
- 配置导入采用独立的保真恢复规则，见第 9 章。

## 5. 路由策略

路由选择分为有副作用的 `pick_plan` 与无副作用的 `peek_plan`：前者处理真实请求，后者仅用于界面预览“当前转发计划”。两者的规则必须保持一致，但预览不得清零用量或修改当前计划。

### 5.1 阈值轮转 `threshold_rotation`

设“可用计划”为已绑定、已启用且 `used_tokens < token_threshold` 的计划。

处理顺序：

1. 若 `current_plan_id` 指向一个可用计划，则固定使用该计划，不进行自动轮转。
2. 若手动指定已失效——计划达阈值、被禁用或被解绑——清除该指定，然后继续自动选择。
3. 未指定当前计划时，按绑定顺序选择第一个可用计划。
4. 若存在启用绑定但全部达到阈值，则清零该聚合器所有绑定用量，并回绕到第一个启用绑定。
5. 仅当没有任何启用绑定时返回“无可用计划”，代理响应 503。

约束与示例：

- 达到阈值后的切换发生在下一次路由选择时；刚完成请求所消耗的 Token 会先计入绑定用量。
- 全部超额时回绕是规定行为，不得改为 503。
- 历史消息中的 Token 不随第 4 步清零。

### 5.2 模型匹配 `model_match`

设“匹配集”为已绑定、已启用且 `models` 精确包含请求模型名的计划。

处理顺序：

1. 请求模型非空且匹配集非空时：
   - 当前计划已在匹配集中：保持当前计划，即粘性路由，即使其他匹配计划用量更少也不切换；
   - 否则：选择匹配集中 `used_tokens` 最少的计划，用量相同取先绑定者，并将结果持久化为当前计划。
2. 无匹配计划，包括请求未携带模型或模型不在任何列表中时：使用当前计划。
3. 当前计划为空、未绑定或已禁用时：回退到第一个启用绑定并固化为当前计划。
4. 没有任何启用绑定时返回“无可用计划”，代理响应 503。

本策略中 `token_threshold` 不参与路由；`used_tokens` 只用于展示和“最少用量”比较，不会因达到阈值而清零或切换。

### 5.3 策略对照

| 场景 | 阈值轮转 | 模型匹配 |
| --- | --- | --- |
| 主要依据 | 绑定顺序、阈值、手动固定 | 请求模型、当前计划粘性、绑定用量 |
| 空 `models` | 无影响 | 不参与匹配，但可作当前计划 |
| 达到阈值 | 跳过；全超额则清零回绕 | 不影响选择 |
| 手动指定失效 | 清除指定并恢复轮转 | 回退第一个启用绑定并固化 |
| 无启用绑定 | 503 | 503 |

## 6. HTTP 代理协议

### 6.1 路由与 URL

- 接受任意 HTTP method 和 path，包括 `/v1/messages`、`/v1/chat/completions`、`count_tokens` 等。
- 上游 URL 为 `base_url` 去除末尾 `/` 后拼接原始 path 与 query。
- 非法 method 返回 405。
- 非空请求体照常转发；空请求体在 POST、PUT、PATCH 时也按空体发送。

### 6.2 客户端鉴权

令牌提取顺序：

1. 优先读取 `Authorization`；`Bearer ` 前缀忽略大小写并剥离，未带该前缀时将整个值作为令牌。
2. 无 `Authorization` 时读取 `x-api-key`。
3. 与聚合器 `auth_token` 完整字符串相等才通过。

鉴权失败返回 401，错误类型为 `authentication_error`，不转发上游。该失败会写入一条消息：`plan_id` 和请求体为空，响应体为本地错误说明文本，模型与 Token 用量为 0。

### 6.3 请求头处理

以下请求头不透传：

```text
host, authorization, x-api-key, content-length, transfer-encoding,
connection, keep-alive, proxy-authorization, proxy-authenticate,
te, trailer, upgrade, accept-encoding
```

其余请求头按原值转发，包括 `anthropic-version`、`anthropic-beta` 等业务头；重复头保留多值。随后强制注入所选计划的令牌：

```http
Authorization: Bearer <计划 AUTH_TOKEN>
x-api-key: <计划 AUTH_TOKEN>
```

客户端原始鉴权头不得传给上游。

### 6.4 响应处理

- 上游 HTTP 状态原样返回；上游 4xx/5xx 不自动切换计划。
- `content-length`、`transfer-encoding`、`connection`、`keep-alive` 不透传，其余响应头透传。
- `Content-Type` 包含 `text/event-stream` 时走 SSE 分支：
  - 通过容量为 64 的通道边读边转发；
  - 同时累积最多 2MB 的落库副本；
  - 在完整流上增量解析 usage，不受落库截断影响；
  - 客户端断开后停止读取上游，但仍保存已接收部分和已解析用量。
- 其他响应走整体读取分支：完整响应上限 64MB，成功后整体返回客户端；用于落库的响应体仍截断至 2MB。
- 非流式响应读取失败或超过 64MB 时，向客户端返回 502，并以 502 落库，即使上游此前已返回成功状态头。

### 6.5 超时、大小与本地错误

| 项目 | 规格 |
| --- | --- |
| 客户端请求体 | 最大 32MB；超限或读取失败返回 400。 |
| 请求体落库 | 最大 2MB，超出添加 `…[已截断]` 标记。 |
| 响应体落库 | 最大 2MB，使用同一截断标记。 |
| 非流式上游响应 | 最大 64MB。 |
| 上游连接超时 | 15 秒。 |
| 连接池空闲超时 | 90 秒。 |
| 请求总超时 | 不设置，以支持长 SSE 流。 |

代理自身产生的错误采用 Anthropic 风格 JSON：

```json
{
  "error": {
    "type": "error_type",
    "message": "中文错误说明"
  }
}
```

主要结果与落库行为：

| 场景 | 客户端状态 | 是否落消息 |
| --- | ---: | --- |
| 客户端鉴权失败 | 401 | 是，无计划；请求体为空，响应体为本地错误说明 |
| 请求体读取失败或超过 32MB | 400 | 否 |
| 非法 method | 405 | 否 |
| 聚合器配置读取失败 | 500 | 否 |
| 路由过程数据库错误 | 500 | 否 |
| 无启用计划 | 503 | 是 |
| 上游请求发送失败 | 502 | 是 |
| 非流式响应读取失败或超过 64MB | 502 | 是 |
| 上游正常或业务错误响应 | 透传上游状态 | 是 |

## 7. Token、模型与消息记录

### 7.1 用量口径

支持两类上游字段：

| 类型 | 输入 | 输出 | 总量 | 缓存 |
| --- | --- | --- | --- | --- |
| OpenAI | `prompt_tokens` | `completion_tokens` | `total_tokens` | 不额外累计 `prompt_tokens_details.cached_tokens` |
| Anthropic | `input_tokens` | `output_tokens` | 有则采用，无则计算 | `cache_read_input_tokens`、`cache_creation_input_tokens` |

规则：

- `usage` 可位于顶层，也可位于 Anthropic `message_start` 的 `message.usage`。
- 未提供显式总量时，`total_tokens = input + output + cache_read + cache_creation`。
- 因缓存计入总量，驱动轮转的绑定用量也包含缓存读与缓存写。
- OpenAI 的 cached tokens 是 prompt tokens 的子集，为避免重复计数，不映射为独立缓存用量。
- SSE 按 `data:` 行增量解析；后续事件的值更新此前值，以覆盖 Anthropic 首事件输入用量和末事件输出用量、OpenAI 末尾 chunk 用量等形式。
- 模型名优先取请求体顶层 `model`，缺失时从 JSON 或 SSE 响应副本提取。请求落库副本因 2MB 截断无法提取时，使用完整请求体重试。

### 7.2 写库与事件顺序

一次已记录请求完成时：

1. 若 `total_tokens > 0`，累加对应绑定的路由用量；
2. 插入消息记录；
3. 查询展示所需名称并构造不含大报文体的 `MessageSummary`；
4. 发出 `message:new` 事件。

若转发期间绑定已被移除，无法找到原绑定时不累加路由用量，但消息仍应保存。消息耗时从代理开始处理请求计时；SSE 包含整个流的持续时间。

### 7.3 消息页面

- 列表字段：时间、聚合器、计划、模型、method/path、状态、Token、耗时。
- 支持按聚合器筛选、分页和手动刷新；默认每页 20 条，接口允许 1–200 条，界面提供 20/50/100。
- 实时刷新默认可用；仅在开启实时刷新且位于第一页时自动刷新，事件防抖 1 秒。
- 列表查询不搬运两个 body 字段；打开详情时再读取完整消息。
- 详情展示请求体、响应体和“客户端 → 聚合器 → 上游计划”的单请求时序图，可从时序步骤定位到对应报文。
- “清空”删除当前筛选范围内的消息；未筛选时清空全部消息。该操作影响历史统计和小计后续查询，但不直接重置绑定路由用量。

## 8. 统计与小计里程

### 8.1 历史统计

所有历史统计以 `messages` 为数据源，包括总 Token、输入、输出、缓存读、缓存写和请求数。请求数是被记录的消息数，因此包含已落库的本地 401、503 等记录。

支持：

- 侧边栏全局累计 Token 和请求数；
- 计划、聚合器各自的累计统计；
- 按天统计：含今天在内的近 N 天，前端补零，支持 7/14/30 天；
- 按小时统计：指定本地日期的 24 个小时，前端补零；
- 按模型统计：全部时间或近 7/14/30 天，按总 Token 降序并计算占比；
- 按天、小时、模型统计均可按聚合器筛选。

时间戳使用本地时间 `YYYY-MM-DD HH:MM:SS`。统计接口天数参数限制为 1–365。

### 8.2 双轨数据约束

| 数据 | 来源 | 清零/重置影响 |
| --- | --- | --- |
| 历史统计 | `messages` 聚合 | 绑定用量清零、阈值回绕、小计重置均不影响；删除消息会影响。 |
| 路由用量 | `aggregator_plans.used_tokens` | 手动重置或阈值全超额回绕会清零；不删除历史消息。 |

### 8.3 小计里程

设置键：

- `trip_started_at`：小计起点；为空表示从未重置，统计全部历史；
- `trip_paused_at`：存在即表示当前暂停；
- `trip_pauses`：已经结束暂停区间的 JSON 数组，每项为 `[start, end]`。

规则：

- 重置只把起点设为当前时间并清除暂停状态与暂停区间，不修改消息。
- 暂停时，统计冻结在暂停时刻。
- 继续时，将 `[paused_at, now)` 加入排除区间；暂停期间的用量之后不补计。
- 暂停区间采用半开语义：暂停时刻的消息不计，恢复时刻的消息计入。
- 侧边栏圆盘单击暂停/继续，双击重置且无二次确认；单击延迟 250ms 以区分双击。

## 9. 配置导入与导出

### 9.1 文件格式

格式标识为 `cpm-config`，当前版本为 1。导出包含全部计划、聚合器及绑定关系，不包含消息或小计设置。

```json
{
  "format": "cpm-config",
  "version": 1,
  "exported_at": "2026-11-25 12:00:00",
  "plans": [
    {
      "ref_id": 1,
      "name": "示例计划",
      "base_url": "https://example.com/api/anthropic",
      "auth_token": "<上游令牌>",
      "remark": "",
      "models": ["claude-sonnet-5"],
      "enabled": true
    }
  ],
  "aggregators": [
    {
      "name": "示例聚合器",
      "port": 8300,
      "auth_token": "<聚合器令牌>",
      "strategy": "model_match",
      "token_threshold": 1000000,
      "plan_refs": [1],
      "current_plan_ref": 1
    }
  ]
}
```

引用与保留规则：

- 文件内以 `ref_id`、`plan_refs`、`current_plan_ref` 建立引用，不依赖数据库自增 ID。
- 聚合器 `auth_token` 原样导出和导入，以复现客户端接入参数。
- `created_at`、`used_tokens` 和运行状态不导出；导入后重新生成创建时间、路由用量归零、服务保持停止。
- 文件包含上游和聚合器明文令牌，必须按敏感凭据保管。

### 9.2 校验

导入要求：

- `format` 必须为 `cpm-config`；高于当前版本的文件拒绝导入。
- 计划名称、URL、令牌和 `ref_id` 合法，且 `ref_id` 不重复。
- 聚合器名称、端口、令牌、策略和阈值合法。
- `plan_refs` 必须引用文件内存在的计划。
- 数据库变更在一个事务中执行；任一数据库导入步骤失败时整体回滚。

### 9.3 合并导入 `merge`

- 文件中的计划和聚合器作为新条目追加，现有配置不变。
- 若端口已被现有配置或本次先前导入项占用，自动在 8300–8399 中分配新端口，并在结果中列出 `旧端口 → 新端口`。
- 原端口未发生逻辑冲突时直接保留，不预先做操作系统 bind 检查；实际启动仍可能发现外部占用。
- 不停止现有运行服务。

### 9.4 替换导入 `replace`

- 界面在模式选择后再次确认该破坏性操作。
- 选定文件后，先向所有运行服务发出停止信号，不等待 SSE 等请求完全排水，再清空计划和聚合器配置并按文件重建。
- 消息和 `settings` 保留，因此历史消息、小计起点和暂停数据不因替换配置而删除。
- 导入后服务不会自动重新启动。
- 数据库回滚不能撤销已经发出的停服操作；导入失败后仍需检查服务状态。

### 9.5 当前计划恢复

- 绑定按 `plan_refs` 顺序恢复并去重。
- `current_plan_ref` 指向文件内计划且该计划已包含在聚合器绑定中时，通过数据库层恢复当前计划，允许忠实复现指向禁用计划的配置。
- 引用未知计划或未绑定计划时忽略该当前计划指定。

## 10. 数据持久化

### 10.1 存储位置与连接

- Windows 数据目录：`%APPDATA%\com.codingplan.manager\cpm.db`。
- 使用 WAL、外键开启、`synchronous=NORMAL`、64MB 页缓存和内存临时存储。
- 全应用共享一个 `Arc<Mutex<rusqlite::Connection>>`，由命令层和代理共同使用。
- 消息和统计命令通过 `spawn_blocking` 执行，避免慢查询阻塞 Tauri 主线程。

### 10.2 逻辑数据表

| 表 | 主要内容 |
| --- | --- |
| `coding_plans` | 计划配置、模型串、启用状态、创建时间。 |
| `aggregators` | 聚合器配置、端口、令牌、策略、阈值、当前计划、创建时间。 |
| `aggregator_plans` | 有序绑定及各绑定路由用量。 |
| `messages` | 请求/响应副本、状态、模型、五类 Token 指标、耗时和关联 ID。 |
| `settings` | 小计里程键值数据。 |

数据库初始化先执行旧库列迁移，再创建统计索引。统计索引采用覆盖索引，避免大 body 所在行回表和溢出页遍历；索引定义变化时通过规范化 DDL 比较自动重建。

### 10.3 敏感数据

- 上游令牌、聚合器令牌、请求体和响应体均以明文形式存于本地数据库。
- 请求和响应可能包含源代码、提示词及其他敏感内容。
- 消息体 2MB 上限是存储截断，不是脱敏；当前无字段级脱敏或加密。
- 配置文件同样包含明文令牌，导出成功提示必须提醒用户妥善保管。

## 11. 桌面界面与运行体验

### 11.1 页面

默认进入“聚合器”页面，侧边栏包含：

1. 聚合器；
2. Coding Plan；
3. 消息记录；
4. 统计。

聚合器列表提供接入参数复制、运行状态、当前计划高亮、累计统计和启停操作。详情包括接入参数、策略切换、当前计划、阈值、用量重置和绑定管理；聚合器不超过 3 个时内联展示，更多时使用抽屉。

### 11.2 实时刷新

`message:new` 载荷不包含请求/响应大字段，仅作为刷新触发器：

- 消息页：防抖 1 秒；
- 聚合器、统计和侧边栏：防抖 1.5 秒。

### 11.3 托盘与退出

- 默认关闭窗口时隐藏到托盘。
- 侧边栏可切换为关闭时弹出退出确认；偏好保存在 `localStorage` 的 `cpm.hideOnClose`。
- 托盘左键或“显示主窗口”恢复界面；“退出”结束应用及全部代理服务。

### 11.4 启动失败

- 数据目录、数据库、托盘或窗口初始化失败时，通过原生对话框展示完整错误链，避免 GUI 应用静默退出。
- panic 钩子也使用原生对话框显示错误。
- 主窗口在应用状态注册完成后创建，避免前端首批命令先于状态初始化执行。

## 12. 非功能性要求

### 12.1 性能

- 消息列表不得读取两个大 body；详情按需读取。
- 高频事件必须防抖，不得每条消息触发一次全量统计查询。
- 统计 SQL 必须使用覆盖索引；修改统计查询或索引时须保留查询计划回归测试。
- SSE 不得在转发前等待完整响应，也不得为了统计把完整流无上限累积在内存中。

### 12.2 一致性与可维护性

- 路由真实选择与界面预览共用同一业务定义，任何路由变更必须同步 `pick_plan` 和 `peek_plan`。
- 新增转发头处理时同步维护请求、响应跳过清单。
- 前端调用 Tauri 命令时参数键使用 camelCase；Rust 参数保持 snake_case，序列化返回字段保持 snake_case。
- 数据库迁移必须先补列再创建依赖这些列的索引。
- 面向用户的界面文本、注释和错误消息使用中文。

## 13. 核心验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 启动聚合器并以正确 Bearer 或 `x-api-key` 调用 | 请求到达绑定上游，客户端原令牌被计划令牌双头替换。 |
| AC-02 | 使用错误聚合器令牌 | 返回 401，不请求上游，留下无计划消息。 |
| AC-03 | 阈值轮转中当前计划达到阈值 | 下一请求跳过该计划；全部超额时清零并回绕，历史统计不变。 |
| AC-04 | 手动固定的阈值计划被禁用 | 清除固定状态并恢复自动轮转。 |
| AC-05 | 模型匹配且当前计划在匹配集 | 保持粘性，不因其他计划用量更低而切换。 |
| AC-06 | 模型匹配且当前计划不在匹配集 | 选择用量最少的匹配计划并持久化；同量取先绑定。 |
| AC-07 | 请求无模型或无匹配模型 | 使用有效当前计划；当前失效时回退第一个启用绑定。 |
| AC-08 | 所有绑定计划均禁用 | 两种策略均返回 503，不做清零回绕。 |
| AC-09 | Anthropic SSE 带缓存用量且流超过 2MB | 流式透传，落库副本截断，但 Token 统计包含完整流尾部输出与缓存。 |
| AC-10 | OpenAI usage 含 cached tokens | 不重复累计缓存；总量沿用上游或按支持的字段计算。 |
| AC-11 | 重置聚合器用量 | 绑定用量归零，消息、历史统计和小计不直接改变。 |
| AC-12 | 小计暂停后继续 | 暂停区间消息永久排除，累计统计不受影响；双击重置不删除消息。 |
| AC-13 | 合并导入存在端口冲突 | 原配置不变，新配置追加，冲突端口自动改配并报告。 |
| AC-14 | 替换导入 | 停止运行服务，保留消息和设置，重建计划、聚合器、绑定和令牌，不自动重启。 |
| AC-15 | 应用重启 | 配置和历史消息保留，代理均处于停止状态。 |
